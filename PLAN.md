# Трейд-бот для Bybit (крипта + акции) — план разработки

> Документ — пошаговый план, по которому приложение можно реализовать самостоятельно.
> Каждый этап заканчивается проверяемым результатом (Definition of Done).

---

## 0. Важные вводные и честные ограничения

1. **Ни одна стратегия не гарантирует прибыль.** Ниже описана стратегия с разумным
   матожиданием на исторических данных, но перед реальными деньгами обязательны:
   бэктест → walk-forward проверка → минимум 4–8 недель на testnet/paper → запуск с малым депозитом.
2. **Акции на Bybit.** Bybit V5 API в первую очередь — крипта (spot, linear/inverse perpetual, options).
   Акции у Bybit доступны как:
   - токенизированные акции (xStocks и аналоги) на споте — торгуются через тот же V5 API как обычные спот-пары;
   - Bybit TradFi (CFD на акции/индексы) — работает через MetaTrader 5, **не через V5 API**.

   Поэтому архитектура строится вокруг **абстракции брокера** (`BrokerAdapter`): первым реализуется Bybit V5,
   а для полноценного фондового рынка подключается отдельный адаптер (например, Alpaca / Interactive Brokers /
   T-Invest API — в зависимости от юрисдикции). Актуальный список инструментов и ограничения API
   нужно проверить в документации Bybit на момент реализации.
3. Бот торгует **только по API-ключу без права вывода средств** (withdraw disabled), с IP-whitelist.

## 5. Торговая стратегия

### 5.1. Идея

Одна стратегия не работает на всех фазах рынка. Поэтому используется
**ансамбль с фильтром режима рынка**:

1. Определяем **режим** (тренд вверх / тренд вниз / флэт / высокая волатильность-хаос).
2. В каждом режиме включаются подходящие под-стратегии.
3. Сигналы взвешиваются и дают **confidence 0–100%** для направления Long/Short.
4. Сделка открывается, только если confidence ≥ порога **и** риск-менеджер разрешает.

Это сочетание (trend-following + mean-reversion с фильтром режима + мультитаймфрейм + ATR-стопы)
— одно из самых устойчивых для систематической торговли: тренд даёт крупные прибыльные сделки,
фильтр режима отсекает основную массу ложных сигналов во флэте.

### 5.2. Таймфреймы (мультитаймфрейм)

| Роль | Крипта (по умолчанию) | Акции |
|------|-----------------------|-------|
| Старший (направление) | 4h | 1D |
| Рабочий (сигнал) | 1h | 1h |
| Младший (точка входа) | 15m | 15m |

Анализ запускается **на закрытии свечи рабочего таймфрейма** (не на каждом тике) — меньше шума и комиссий.

### 5.3. Определение режима рынка (`regime.py`)

- **ADX(14)** на рабочем ТФ: > 25 — тренд, < 20 — флэт, между — переходный.
- **EMA(200)** на старшем ТФ: цена выше — разрешены лонги в приоритете, ниже — шорты.
- **ATR(14) / цена** (нормированная волатильность) в перцентиле за 90 дней:
  > 95-го перцентиля — режим «хаос», новые сделки **не открываются**.
- Режимы: `TREND_UP`, `TREND_DOWN`, `RANGE`, `CHAOS`.

### 5.4. Под-стратегии и их сигналы

Каждая под-стратегия возвращает `score ∈ [-1; +1]` (минус — шорт, плюс — лонг).

**A. Trend-following (активна в TREND_*)**
- EMA(21) > EMA(55) и обе растут → +;
- откат к EMA(21) / VWAP с отскоком на младшем ТФ → вход;
- MACD-гистограмма в сторону тренда;
- подтверждение объёмом: объём свечи > SMA(20) объёма.

**B. Mean reversion (активна в RANGE)**
- цена у нижней полосы Bollinger(20, 2) + RSI(14) < 30 + бычья дивергенция RSI → +;
- зеркально для шорта;
- цель — средняя линия Bollinger.

**C. Breakout (переход RANGE → TREND)**
- сжатие Bollinger (ширина в нижних 10% за 120 свечей);
- пробой диапазона Donchian(20) с объёмом > 1.5× среднего;
- ретест уровня на младшем ТФ.

**D. Контекстные фильтры (модификаторы, не самостоятельные сигналы)**
- Крипта: funding rate (экстремально положительный → штраф лонгам), open interest, дисбаланс стакана.
- Акции: торговая сессия (не торговать первые/последние 15 минут), даты отчётности (не держать через отчёт).
- Корреляция с BTC для альткоинов (если BTC в сильном падении — лонги альтов штрафуются).

### 5.5. Расчёт уверенности (`confidence.py`)

```
raw = Σ (w_i × score_i)          # веса зависят от режима
      × mtf_alignment            # 1.0 если старший ТФ согласен, 0.5 если нейтрален, 0 если против
      × filters_multiplier        # funding, сессия, корреляция: 0..1

confidence = |raw| × 100 %,  direction = sign(raw)
```

Веса по режиму (стартовые, затем оптимизируются в бэктесте):

| Режим | Trend | MeanRev | Breakout |
|-------|-------|---------|----------|
| TREND_UP / DOWN | 0.6 | 0.1 | 0.3 |
| RANGE | 0.1 | 0.6 | 0.3 |
| CHAOS | — торговля запрещена — |||

**Этап 2 (ML-калибровка):** обучить LightGBM-классификатор на признаках (индикаторы, режим, score под-стратегий)
с целевой переменной «TP достигнут раньше SL» (triple-barrier labeling). Выход модели — откалиброванная
вероятность (isotonic/Platt). Итоговая уверенность = среднее правил и модели. Обучение только walk-forward,
чтобы избежать заглядывания в будущее.

**Порог входа** — настраиваемый, по умолчанию 65%. Порог выбирается по бэктесту так,
чтобы оптимизировать не число сделок, а expectancy и Profit Factor.

### 5.6. Стоп-лосс и тейк-профит

- **SL** = за ближайшим свинг-экстремумом, но не ближе `1.5 × ATR(14)` и не дальше `3 × ATR`.
- **TP** в две части:
  - TP1 = `1.5R` (R — расстояние до стопа) → закрыть 50%, стоп перенести в безубыток (+комиссия);
  - TP2 = `3R` или трейлинг-стоп по `Chandelier Exit (ATR×3)` для остатка.
- Для mean-reversion: TP = средняя Bollinger, минимальный R:R 1:1.5, иначе сделка не открывается.
- **Минимальный R:R = 1:2 по средневзвешенной цели** — фильтр перед отправкой ордера.
- SL и TP **выставляются на бирже** сразу вместе с ордером (`stopLoss`/`takeProfit` в V5, `tpslMode=Partial`
  для частичных TP), чтобы позиция была защищена даже при падении бота.
- Тайм-стоп: если за N свечей (по умолчанию 24 на рабочем ТФ) цена не дошла до TP1 — закрыть.

### 5.7. Условия, когда сделка НЕ открывается

- режим CHAOS; спред > порога; низкая ликвидность;
- уже открыта позиция по этому инструменту или коррелирующему (корр. > 0.8) сверх лимита;
- сработал дневной/недельный лимит убытка;
- до новостей/отчёта < заданного времени; рынок акций закрыт.

## 6. Риск-менеджмент (настраиваемый)

### 6.1. Размер позиции

```
risk_amount   = equity × risk_per_trade_%
stop_distance = |entry − stop_loss|
qty           = risk_amount / (stop_distance + комиссии_и_проскальзывание_на_единицу)
qty           = округлить вниз до qtyStep, проверить minQty и maxQty
leverage      = минимальное плечо, при котором хватает маржи (не параметр прибыли!)
```

Плечо не увеличивает риск — риск задаётся расстоянием до стопа и размером позиции.
Максимальное плечо ограничено настройкой (по умолчанию 5×), проверка, что цена ликвидации дальше стопа минимум на 1 ATR.

### 6.2. Профили риска

| Параметр | Conservative | **Moderate (по умолч.)** | Aggressive |
|----------|--------------|--------------------------|------------|
| Риск на сделку | 0.5% | **1.0%** | 2.0% |
| Макс. одновременных позиций | 3 | 5 | 8 |
| Макс. суммарный открытый риск | 2% | 4% | 8% |
| Дневной лимит убытка | 2% | 3% | 5% |
| Недельный лимит убытка | 4% | 6% | 10% |
| Макс. просадка → остановка бота | 10% | 15% | 25% |
| Порог confidence | 72% | 65% | 60% |
| Макс. плечо | 3× | 5× | 10× |

Профиль **Custom** — все поля редактируются в панели, с валидацией диапазонов (например, риск 0.1–3%).

### 6.3. Динамическая коррекция риска

- После 3 убыточных сделок подряд риск × 0.5 до первой прибыльной.
- При просадке > половины лимита — риск × 0.5.
- Масштаб по confidence (опционально): `risk × clamp((conf − порог)/(100 − порог), 0.5, 1.0)`.
- Никакого мартингейла и усреднения убыточных позиций.

### 6.4. Защитные механизмы

- Kill switch (кнопка в панели + команда в Telegram): отмена ордеров, закрытие позиций, стоп движка.
- Circuit breaker: > N ошибок API за M минут → пауза торговли и алерт.
- Сверка (reconciliation) каждые 60 сек: позиции в БД == позиции на бирже; расхождение → алерт, биржа — источник истины.
- Позиция без стопа на бирже → немедленно выставить стоп или закрыть.

## 7. Интеграция с Bybit V5

| Задача | Эндпоинт / канал |
|--------|------------------|
| История свечей | `GET /v5/market/kline` |
| Инфо об инструментах | `GET /v5/market/instruments-info` (tickSize, qtyStep, minOrderQty) |
| Тикеры, funding, OI | `GET /v5/market/tickers`, `/v5/market/funding/history`, `/v5/market/open-interest` |
| Свечи/стакан в реальном времени | public WS: `kline.{interval}.{symbol}`, `orderbook.50.{symbol}` |
| Баланс | `GET /v5/account/wallet-balance` (Unified Trading Account) |
| Плечо | `POST /v5/position/set-leverage` |
| Ордер | `POST /v5/order/create` (`orderLinkId` для идемпотентности, `stopLoss`, `takeProfit`) |
| Изменение SL/TP / трейлинг | `POST /v5/position/trading-stop` |
| Отмена | `POST /v5/order/cancel`, `/v5/order/cancel-all` |
| Позиции/исполнения | `GET /v5/position/list`, `/v5/execution/list`, `/v5/position/closed-pnl` |
| Приватные события | private WS: `order`, `execution`, `position`, `wallet` |

Технические моменты:
- Подпись HMAC-SHA256, `recv_window`, синхронизация времени с `GET /v5/market/time`.
- Соблюдение rate limit (читать заголовки `X-Bapi-Limit-Status`), очередь запросов с token bucket.
- Reconnect WS с экспоненциальной задержкой + ping каждые 20 сек; после переподключения — докачка пропущенных свечей по REST.
- Testnet: `api-testnet.bybit.com` для режима paper; переключение одной настройкой.
- Категории: `spot`, `linear` (USDT-перпетуалы — основной рынок бота), токенизированные акции — `spot`.

### 7.1. Интерфейс `BrokerAdapter`

```python
class BrokerAdapter(ABC):
    async def get_candles(self, symbol, tf, start, end) -> list[Candle]: ...
    async def subscribe_candles(self, symbols, tf, callback): ...
    async def get_instrument(self, symbol) -> Instrument: ...     # шаги цены/объёма, комиссии, сессии
    async def get_balance(self) -> Balance: ...
    async def get_positions(self) -> list[Position]: ...
    async def place_order(self, req: OrderRequest) -> OrderResult: ...  # с SL/TP
    async def amend_stops(self, symbol, sl, tp): ...
    async def close_position(self, symbol, qty=None): ...
    async def cancel_all(self, symbol=None): ...
    def market_type(self) -> Literal["crypto", "stock"]: ...
    def is_market_open(self, symbol, ts) -> bool: ...
```

Отличия акций, которые учитывает адаптер: торговые сессии и выходные, гэпы на открытии
(стоп может исполниться хуже — учитывать в риске), отсутствие шортов/плеча у части брокеров,
лотность, T+1 расчёты, другие комиссии.

## 9. Веб-панель

### 9.1. Страницы

1. **Dashboard**
   - карточки: Equity, PnL сегодня / неделя / месяц / всё время (в $ и %), открытый риск, текущая просадка;
   - equity-кривая с drawdown под ней;
   - статус бота (running / paused / stopped), режим (paper/live), состояние подключения к бирже;
   - кнопки **Пауза**, **Старт**, **KILL SWITCH** (с подтверждением).
2. **Открытые позиции** — инструмент, направление, вход, текущая цена, SL/TP (визуально шкалой), нереализованный PnL в $ и R, confidence на входе, время в сделке; кнопки «закрыть», «в безубыток», «изменить SL/TP».
3. **История сделок** — таблица с фильтрами (период, инструмент, рынок, направление, результат, стратегия), экспорт CSV.
4. **Карточка сделки** — свечной график (lightweight-charts) с отметками входа/выхода, линиями SL/TP, разбивка confidence по компонентам, лог ордеров.
5. **Сигналы** — лента всех сигналов, включая отклонённые, с причиной отказа (полезно для настройки порога).
6. **Статистика**
   - Win rate, Profit Factor, Expectancy (в R), средний выигрыш/проигрыш, макс. просадка, Sharpe, Sortino, Calmar;
   - распределение R-multiple (гистограмма), PnL по инструментам, по дням недели/часам, по стратегиям, по режимам рынка;
   - **калибровка confidence**: фактический win rate в корзинах 60–65%, 65–70%… — показывает, можно ли доверять уверенности.
7. **Бэктест** — запуск с параметрами, сравнение прогонов, walk-forward отчёт.
8. **Настройки** — профиль риска и все параметры, список инструментов, таймфреймы, веса стратегий, порог, API-ключи (только запись, отображаются маской), Telegram.
9. **Логи** — события движка и risk_events с фильтром уровня.

### 9.2. Обновление в реальном времени

WebSocket `/ws`: события `equity`, `position_update`, `trade_opened`, `trade_closed`, `signal`, `bot_status`, `alert`.

### 9.3. Безопасность панели

- Логин + пароль (argon2) + TOTP 2FA, JWT с коротким сроком жизни;
- доступ только через HTTPS (Caddy/Nginx + Let's Encrypt), желательно за VPN/Tailscale;
- API-ключи биржи хранятся зашифрованными (Fernet, мастер-ключ из переменной окружения).

## 10. Бэктест и валидация

1. Загрузка истории: минимум 2–3 года для крипты (включая бычий, медвежий и боковой рынок), 5+ лет для акций.
2. Реалистичное исполнение: комиссии taker/maker, проскальзывание (напр. 0.05% или доля ATR), funding для перпетуалов,
   консервативная обработка свечи, где задеты и SL, и TP (считать, что сработал SL).
3. **Walk-forward**: оптимизация на 6 мес → проверка на следующих 2 мес → сдвиг окна. Итог считается только по out-of-sample.
4. Защита от переобучения: мало параметров, проверка устойчивости (соседние значения параметров дают похожий результат),
   Monte-Carlo перемешивание сделок для оценки разброса просадки.
5. Критерии допуска к paper-торговле (ориентиры): Profit Factor > 1.3, Expectancy > 0.15R, макс. просадка < лимита профиля,
   > 100 сделок в выборке, результат положителен на большинстве walk-forward окон.
6. Критерии допуска к live: результаты paper не хуже бэктеста более чем на ~30%.

## 12. Тестирование

- **Юнит**: индикаторы против эталонов (TA-Lib/TradingView), sizing (округление к qtyStep, minQty), лимиты риска.
- **Property-based**: для любых входных данных риск сделки ≤ заданного, стоп всегда с правильной стороны от входа.
- **Интеграционные**: адаптер против Bybit testnet (размещение/отмена ордера, SL/TP, чтение позиций).
- **Сценарные**: обрыв WS в момент исполнения, рестарт бота с открытыми позициями, частичное исполнение, отказ биржи (retCode ≠ 0).
- **Совпадение backtest vs paper**: прогон бэктеста на периоде paper-торговли должен давать близкие сделки.
