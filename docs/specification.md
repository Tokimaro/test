# Спецификация решения Tradebot

Версия 0.1.0, сентябрь 2026.

## 1. Назначение

Автоматический торговый бот для **спота Bybit** с веб-панелью и Telegram-управлением. Держит
криптовалюты, пока у них растущий тренд, и уходит в USDT, когда тренд пропадает. Цель — меньшие
просадки, чем при простом удержании BTC, при сопоставимой или большей доходности.

Бот не использует плечо, шорты, фьючерсы и не делает внутридневных сделок: всё это было проверено
и отброшено (раздел 11).

## 2. Возможности

| Область | Что умеет |
|---|---|
| Торговля | Портфель из 8 монет спота Bybit к USDT; целевые доли раз в день, ребалансировка раз в неделю рыночными ордерами |
| Режимы | `paper` — симуляция на реальных ценах Bybit; `paper` + ключи testnet — настоящие ордера на testnet; `live` — реальные деньги; `backtest` — проверка на истории |
| Риск | Три профиля (целевая волатильность 15/25/40%) и свой; лимит доли монеты; остановка при просадке; circuit breaker при серии ошибок API; kill switch |
| Надёжность | Идемпотентные ордера, сверка с кошельком, восстановление после рестарта, защита от устаревших данных, автопереподключение WebSocket |
| Панель | Обзор, портфель и целевые доли, сделки, журнал долей, статистика, бэктест, настройки, журнал событий |
| Telegram | Уведомления о сделках и алертах; команды `/status`, `/positions`, `/pause`, `/resume`, `/kill CONFIRM` |
| Безопасность | Вход с паролем и 2FA (TOTP), защита от перебора, шифрование ключей API в БД, панель только на localhost |
| Аналитика | Бэктест тем же кодом, что и в торговле; экспорт сделок в CSV; кривая капитала; история изменений настроек |

## 3. Поддерживаемые рынки и пары

| | |
|---|---|
| Биржа | Bybit, API V5 (REST и WebSocket), mainnet и testnet |
| Рынок | Спот (`category: spot`) |
| Котировка | USDT |
| Пары по умолчанию | **BTCUSDT, ETHUSDT, SOLUSDT, XRPUSDT, DOGEUSDT, ADAUSDT, TRXUSDT, BCHUSDT** |
| Другие пары | Технически — любая спотовая пара Bybit к USDT: параметры инструмента (шаг цены, шаг объёма, минимальная сумма ордера) бот запрашивает у биржи. Стратегия проверялась только на этих 8 монетах и на 12 волатильных альткоинах (там результат хуже, см. [volatile-pairs.md](volatile-pairs.md)) |
| Таймфрейм | Дневные свечи (закрытие в 00:00 UTC) |
| Не поддерживается | Фьючерсы, перпетуалы, маржа, шорт — конфигурация не даст их включить. Акции США (Alpaca): адаптер есть, но рынок выключен и включить его нельзя, пока стратегия на акциях не проверена |

Изменение списка монет — в панели или в `backend/config/default.yaml`, требует перезапуска.

## 4. Стратегия

**Дневной тренд «лонг или кэш»** (time-series momentum, только лонг). Подробно и с результатами
проверки — [strategy-selection.md](strategy-selection.md).

1. Каждый день после закрытия дневной свечи для каждой монеты: сигнал = среднее знаков доходности
   за 20, 60 и 120 дней, отрицательная часть обрезается (0, ⅓, ⅔ или 1).
2. Доля = сигнал / √(число монет) × целевая волатильность / волатильность монеты за 30 дней
   (множитель ≤ 5). Сумма долей ≤ 100%, остаток — в USDT.
3. Раз в неделю (по умолчанию понедельник, UTC) портфель приводится к целевым долям: сначала
   продажи, потом покупки. Изменения меньше 1% капитала не торгуются; выход из монеты — целиком.
4. Стоп-лоссов нет: монета продаётся, когда пропадает тренд.
5. Первый расчёт после запуска сразу собирает портфель.

Параметры (в панели): горизонты тренда, окно волатильности, день ребалансировки, фильтр
BTC > 200-дневной средней (выключен), минимальное изменение доли.

**Капитал стратегии** — свободные USDT плюс монеты из списка на счёте. Другие активы счёта бот
не трогает. Рекомендуется отдельный субаккаунт.

## 5. Результаты проверки

8 монет, комиссия 0.1% + проскальзывание 0.05% на сторону. Параметры выбраны на 2018–2021, проверка
вне выборки — 2022-01 → 2026-09.

| | Sharpe | Доходность, % в год | Макс. просадка |
|---|---|---|---|
| **Бэктест бота** | **0.90** | **23.3** | **−23.9%** |
| Удержание BTC | 0.51 | 14.1 | −66.9% |

Ограничения: нижняя граница 95% доверительного интервала Sharpe около нуля; в медвежьем рынке
стратегия теряет (меньше рынка); прибыль не гарантируется.

## 6. Архитектура

```
                  ┌─────────────── Docker Compose (один сервер) ───────────────┐
 Bybit REST/WS ◄──┤ backend (Python 3.12, FastAPI, один процесс)               │
                  │   market/feed ─► strategy/trend ─► core/engine ─► execution│
 Telegram API ◄───┤   risk/manager, circuit breaker     brokers/bybit | paper  │
                  │   api (REST + WebSocket) + статическая панель React        │
 Браузер ─(SSH/VPN/HTTPS)─► 127.0.0.1:8000                                     │
                  │ db (PostgreSQL 16 + TimescaleDB) ◄── 127.0.0.1:5432         │
                  └────────────────────────────────────────────────────────────┘
```

| Модуль (`backend/app/`) | Назначение |
|---|---|
| `brokers/bybit` | Клиент REST V5 с подписью запросов, WebSocket с ping и переподключением (1–30 с), адаптер ордеров и балансов |
| `brokers/paper` | Симуляция исполнения на реальных ценах с комиссией и проскальзыванием |
| `brokers/alpaca` | Акции США (выключено) |
| `market` | Поток свечей без пропусков и дублей, дозагрузка истории, хранилище свечей |
| `strategy/trend` | Расчёт целевых долей; тест сверяет его с исследовательским кодом до 1e-12 |
| `core/engine` | Портфельный движок: ежедневный расчёт, ребалансировка, сверка, kill switch |
| `execution` | Отправка ордеров с клиентским `orderLinkId`, разрешение неопределённых ответов |
| `risk` | Профили риска, остановка по просадке, circuit breaker (5 ошибок API за 10 минут → пауза) |
| `backtest` | Бэктест с теми же правилами, метрики |
| `api` | REST и WebSocket для панели, аутентификация, CLI пользователей |
| `notify` | Telegram: уведомления и команды |
| `research` | Код исследования стратегий (ботом не используется) |

## 7. Данные

Таблицы PostgreSQL: `instruments`, `candles`, `signals` (журнал целевых долей), `trades`
(владения монетами), `orders`, `executions`, `equity_snapshots`, `settings` (с историей
изменений), `risk_events`, `backtest_runs`, `users`, `secrets` (зашифрованные ключи),
`runtime_state`. Миграции — Alembic, применяются автоматически при старте контейнера.

## 8. Надёжность

* **Идемпотентность ордеров:** у каждого ордера клиентский `orderLinkId`; при таймауте бот
  выясняет судьбу ордера у биржи, а не отправляет его повторно.
* **Сверка с кошельком** — периодически и после рестарта; объёмы берутся с биржи.
* **Устаревшие данные:** если нет дневной свечи какой-либо монеты, расчёт пропускается и
  приходит алерт.
* **Пыль:** остатки меньше минимальной суммы ордера Bybit не торгуются.
* **Circuit breaker:** серия ошибок API ставит торговлю на паузу с уведомлением.
* **Остановка по просадке** (по желанию): продать всё в USDT и ждать ручного возобновления.
* **Kill switch** — из панели или `/kill CONFIRM`: продать монеты стратегии и остановиться.
* **Защита режимов:** в paper ключи mainnet не принимаются; live требует `TB_BYBIT_TESTNET=false`.

## 9. Безопасность

* Панель слушает только `127.0.0.1`; доступ — SSH-туннель, VPN/Tailscale или HTTPS-прокси.
* Вход: пароль (argon2) + TOTP, ограничение попыток по логину и IP, сессия JWT на 60 минут.
* Ключи Bybit — в `.env` или в БД в зашифрованном виде (Fernet); в панели показываются замаскированными.
* Telegram-команды — только из заданного чата (в группе — только от указанных администраторов).
* Требования к ключу API: только спотовая торговля, без вывода и переводов, привязка к IP сервера.

## 10. Интерфейсы

**Веб-панель:** Обзор (капитал, статус, кривая капитала), Портфель (владения и целевые доли,
закрытие позиции, ручная ребалансировка), Сделки (с деталями и CSV), Доли (журнал сигналов),
Статистика, Бэктест, Настройки (риск, стратегия, ключи API, история изменений), Журнал (события
риска), пауза/возобновление/kill switch.

**REST API** (`/api`, JWT): `auth/login`, `auth/me`, `status`, `positions`,
`positions/{symbol}/close`, `control/rebalance|pause|resume|kill`, `trades`, `trades.csv`,
`trades/{id}`, `signals`, `equity`, `stats`, `candles/{symbol}`, `risk-events`, `settings`,
`settings/history`, `secrets`, `secrets/bybit`, `backtests`; `health` без авторизации; WebSocket —
события в реальном времени.

**CLI** (в контейнере): `python -m app.api.users create|passwd <login>`,
`python -m app.market.backfill`, `python -m app.backtest.cli`.

## 11. Что проверено и отклонено

~25 стратегий: скальпинг, Smart Money Concepts (FVG, order blocks, снятие ликвидности), пробои,
VWAP, возврат к среднему, кросс-секционный моментум, шорты, ML (Ridge, LightGBM, нейросеть).
После комиссий и честной симуляции ни одна не дала устойчивого результата вне выборки —
[research-strategies.md](research-strategies.md), [intraday-strategies.md](intraday-strategies.md),
[volatile-pairs.md](volatile-pairs.md).

## 12. Требования к развёртыванию

Сервер 2 vCPU / 4 ГБ RAM / 40 ГБ SSD (минимум 1 vCPU / 2 ГБ + swap / 20 ГБ), Ubuntu 24.04 LTS,
Docker, постоянный IPv4, точное время (chrony), размещение в стране, разрешённой Bybit.
Пошагово — [deployment.md](deployment.md).

## 13. Известные ограничения

* Работа с Bybit проверена автотестами на документированных ответах API; первые реальные сделки
  нужно контролировать вручную.
* Один счёт Bybit на экземпляр бота; одна стратегия.
* Исполнение — рыночными ордерами в начале дня, возможно проскальзывание сверх заложенных 0.05%.
* Уведомления — только Telegram; при полном отказе сервера нужен внешний мониторинг.
