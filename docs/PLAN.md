# План разработки: артиллерийский калькулятор для WARDOGS

## 1. Цель

Маленькое самостоятельное приложение. Пользователь вводит положение орудия и цели, программа отвечает, как выставить орудие для выстрела:

- **азимут** (направление, в градусах);
- **возвышение** (в милах по шкале прицела самого орудия);
- **заряд / траектория** (настильная или навесная), если у орудия их несколько;
- **время полёта** снаряда, чтобы было понятно, когда смотреть на разрыв.

**Ограничения:**
- Приложение **не читает и не меняет** память игры, её файлы и сетевой трафик. Никаких инжектов и оверлеев поверх игры. Все данные вводит пользователь вручную.
- Работает офлайн, без регистрации и без сервера.

## 2. Что известно о механике игры (собрать и проверить в игре на этапе 0)

| Орудие | Калибр | Дальность | Перезарядка | Режимы |
|---|---|---|---|---|
| **L81** (строится игроком) | 81 мм | ~132–684 м (эффективная), ближе 132 м стрелять нельзя | 6.5 с | один |
| **SPH-2** | 155 мм | ~735–2629 м | 27 с | настильная траектория (~1181–2629 м) и навесная (~735–2629 м) |

- Орудие наводят двумя числами: азимут (°) и возвышение (мил). **Больше мил → круче дуга → ближе выстрел.**
- **У прицела своя шкала мил.** Значения из НАТО-таблиц (6400 мил) или от другого орудия не подойдут. Поэтому нужны свои таблицы стрельбы для каждого орудия и режима.
- Разница высот между орудием и целью заметно сдвигает точку падения, её нужно учитывать.

> Эти цифры взяты из открытых источников (публичные калькуляторы и гайды), в игре их никто не перепроверял. Этап 0 нужен, чтобы получить точные данные.

## 3. Модель расчёта

### 3.1 Геометрия
- Вход: координаты орудия `(x₁, y₁, h₁)` и цели `(x₂, y₂, h₂)` в метрах. Их можно ввести вручную или получить из сетки карты (квадрат + клавиатура, см. этап 3).
- Дистанция: `d = √((x₂−x₁)² + (y₂−y₁)²)`.
- Азимут: `az = (atan2(x₂−x₁, y₁−y₂) · 180/π + 360) mod 360`. Север = 0°, ось Y карты направлена вниз. Направление осей сверить с компасом в игре.
- Перепад высот: `Δh = h₂ − h₁`.

### 3.2 Возвышение
Основной подход работает по **таблицам стрельбы**:
1. Для каждого орудия и режима хранится таблица `дистанция (м) → возвышение (мил) [+ время полёта]`. Её собирают в игре.
2. Для дистанции `d` значение находится линейной интерполяцией между соседними строками таблицы.
3. **Поправка на высоту.** Вариант А, простой: в таблице есть колонка «Δмил на 100 м перепада», и поправка считается как `Δмил · Δh / 100`. Вариант Б, точный: по таблице подбираются начальная скорость `v` и перевод «мил прицела ↔ реальный угол». Затем угол решается из уравнения баллистики без сопротивления воздуха:
   `θ = atan((v² ± √(v⁴ − g(g·d² + 2·Δh·v²))) / (g·d))`
   Знак «−» даёт настильную траекторию, «+» даёт навесную. Если корень отрицательный, цель вне досягаемости.
   Начинаем с варианта А. На вариант Б переходим, если точности не хватит (критерий в разделе 6).
4. Если дистанция меньше минимальной или больше максимальной, программа выдаёт понятную ошибку, а не число.

### 3.3 Корректировка после промаха
Пользователь указывает, где упал снаряд: «перелёт/недолёт N м, влево/вправо M м». Программа пересчитывает координаты цели и выдаёт новые азимут и возвышение.

## 4. Технологии

- **TypeScript + Vite**: статическое веб-приложение (SPA). Открывается в браузере на втором мониторе или на телефоне и работает офлайн как PWA. Ставить ничего не нужно.
- Логика расчёта — чистые функции без зависимостей в отдельном модуле `core/`. Их легко тестировать и при необходимости переиспользовать в CLI или десктоп-обёртке.
- Тесты: **Vitest**. Линт и форматирование: ESLint + Prettier.
- Таблицы стрельбы и параметры карт лежат в JSON в `data/`, чтобы после патча игры обновлять их без правки кода.
- Хостинг: GitHub Pages (необязательно).

Структура:
```
src/
  core/            # чистая математика
    geometry.ts    # дистанция, азимут, перевод сетки карты в метры
    tables.ts      # загрузка и интерполяция таблиц стрельбы
    solver.ts      # итоговый расчёт: заряд, режим, мил, время полёта
    correction.ts  # корректировка после промаха
  data/
    weapons/l81.json, sph2.json
    maps/*.json    # размер карты, шаг сетки
  ui/              # формы ввода и вывод решения
tests/
```

Формат таблицы (пример):
```json
{
  "id": "sph2", "name": "SPH-2", "modes": [
    { "id": "low",  "minRange": 1181, "maxRange": 2629,
      "rows": [ { "range": 1200, "mil": 0, "tof": 0, "dMilPer100mUp": 0 } ] },
    { "id": "high", "minRange": 735,  "maxRange": 2629, "rows": [] }
  ]
}
```
Значения здесь условные. Настоящие собираются на этапе 0.

## 5. Этапы

### Этап 0. Сбор данных (без кода, в игре)
- [ ] Для L81 и для каждого режима SPH-2 найти в игре таблицу на прицеле или отстрелять её вручную: шаг 50 м (L81) и 100 м (SPH-2), фиксируя мил и время полёта.
- [ ] Отстрелять несколько точек с перепадом высот ±20…50 м и оценить поправку на высоту.
- [ ] Проверить шкалу азимута: 0° = север, по часовой стрелке. Проверить, есть ли в игре ветер или разброс.
- [ ] Выяснить размеры карт и шаг сетки (квадрат, клавиатура).
- **Результат:** `data/weapons/*.json` и `data/maps/*.json`.

### Этап 1. Ядро расчёта (MVP-логика)
- [ ] Инициализировать проект: Vite + TS, Vitest, ESLint, Prettier, CI через GitHub Actions (lint + test).
- [ ] `geometry.ts`: дистанция и азимут, с тестами на все четыре четверти и граничные случаи.
- [ ] `tables.ts`: валидация JSON, интерполяция, ошибки выхода за диапазон.
- [ ] `solver.ts`: выбор режима (по умолчанию самый быстрый допустимый, навесной — по запросу) и поправка на высоту.
- **Готово, когда** расчёт по точкам таблицы совпадает с исходными значениями, а покрытие `core/` ≥ 90%.

### Этап 2. Интерфейс MVP
- [ ] Форма: орудие (L81 / SPH-2), координаты и высоты орудия и цели в метрах.
- [ ] Вывод: крупно азимут и мил, заряд или режим, время полёта. Для SPH-2 показывать оба варианта, если допустимы оба.
- [ ] Сохранять последние позиции орудия в `localStorage`.
- [ ] Тёмная тема, адаптивная вёрстка для телефона.
- **Готово, когда** расчёт делается за 3–4 поля ввода, а результат читается с расстояния вытянутой руки.

### Этап 3. Удобный ввод
- [ ] Ввод по сетке карты: `C7-5` (квадрат + клавиатура 1–9) переводится в метры.
- [ ] Альтернатива: ввод «дистанция + азимут» с дальномера или бинокля (если в игре такое есть).
- [ ] Необязательно: схема карты, по которой можно кликнуть. Используются только самостоятельно нарисованные подложки или подложки, загруженные пользователем. Ассеты игры в репозиторий не кладём.

### Этап 4. Корректировка и удобства
- [ ] Корректировка после промаха (раздел 3.3).
- [ ] Несколько сохранённых целей, быстрое переключение между ними.
- [ ] PWA: работа полностью офлайн, установка на телефон.
- [ ] Горячие клавиши для ввода с клавиатуры.

### Этап 5 (по желанию). Точная модель
- [ ] Реализовать вариант Б из раздела 3.2 (подбор `v` и калибровка шкалы прицела) и сравнить его с вариантом А на тестовых выстрелах.

## 6. Критерии качества

- Попадание в радиус поражения: 10 м для L81 и примерно 7.5–20 м для SPH-2, с первого выстрела в ≥ 80% тестовых стрельб по ровной местности и в ≥ 70% с перепадом высот.
- Расчёт мгновенный (< 50 мс), без сети.
- Обновление под патч игры требует правки только JSON-данных.

## 7. Риски и открытые вопросы

| Риск / вопрос | Как снимаем |
|---|---|
| Таблицы изменятся после патча | Данные в JSON, в файле указана версия игры |
| Скрытый разброс или ветер в игре | Проверить на этапе 0. Если есть, показывать ожидаемое рассеивание, а не одну точку |
| Неизвестен способ ввода координат, который удобнее игрокам | Уточнить у пользователя: сетка карты или дальномер |
| Нужны ли другие орудия и снаряды (дым, осветительные) | Структура данных поддерживает их без изменения кода |
| Правила игры о сторонних инструментах | Приложение не взаимодействует с игрой. Всё равно перепроверить EULA и правила |
